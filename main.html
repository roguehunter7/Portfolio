How traffic reaches the container and how code reaches the server:

      (Secure Push-Based Update) <-----------┘

1. Stealth Origin: My infrastructure remains invisible. The VPC Firewall drops all public traffic. Connections are only established via Cloudflare Zero Trust (for users) and GCP Identity-Aware Proxy (for deployments).

2. Hardened Runtime: The site runs on the official nginxinc/nginx-unprivileged:alpine-slim image. It executes as a non-root user (UID 101), ensuring that even in the event of a process breach, the attacker has no system-level privileges.

3. Push-Based CI/CD: I replaced the legacy polling model with a modern GitHub Actions pipeline. It securely tunnels through IAP to trigger atomic container updates only when code is merged to main.

Architectural Logic

Why Terraform?
Manual clicks are errors waiting to happen. I use Terraform with a GCS Remote Backend. This ensures my infrastructure is version-controlled, idempotent, and recoverable in seconds.
Why Systemd GitOps?
A GCP e2-micro has only 1GB RAM. Traditional CI/CD runners (Jenkins/GitHub Actions) would trigger an OOM crash. I wrote a native Bash + Systemd poller to handle GitOps with near-zero overhead.
