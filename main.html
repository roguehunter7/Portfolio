I specialize in architecting secure, automated infrastructure. This site serves as a live case study for a zero-ingress cloud environment, demonstrating the transition from initial resource constraints to an enterprise-grade CI/CD pipeline.

Phase 1: Bootstrapping

Native Resource Polling

Constraint: The GCP e2-micro instance is limited to 1GB of RAM. Standard CI/CD runners (like GitHub Actions Runners or Jenkins) posed a high risk of triggering Out-Of-Memory (OOM) events.

Architecture: A pull-based GitOps loop using systemd.timer and a native Bash script. The system polled the GitHub API every 2 minutes for SHA deltas, minimizing memory overhead.

Phase 2: Refactored

Push-Based IAP Tunneling

Requirement: Transition to an instant, push-based model while maintaining a zero-ingress security posture (no public open ports).

Architecture: Replaced polling with GitHub Actions. Utilized GCP Identity-Aware Proxy (IAP) to securely tunnel SSH deployments via Port 22 without exposing the port to the public internet.

System Architecture

Provisioned via Terraform using a GCS Remote Backend for state consistency across development environments.

Key Engineering Decisions

  • Stealth Origin: The origin server is entirely unreachable via public IP. By utilizing Cloudflare Zero Trust Tunnels for egress and IAP for management, the attack surface is minimized to the edge layer.
  • Runtime Hardening: The application runs as a non-root user (UID 101) inside an unprivileged container. This prevents a compromised service from gaining escalated privileges on the host Debian OS.
  • Idempotency: Infrastructure is managed as code. Every firewall rule and network configuration is version-controlled, allowing for deterministic redeployments.

Roadmap: Phase 3

Implementation of Workload Identity Federation to replace long-lived Service Account keys with OIDC-based authentication. Exploring multi-cloud expansion to AWS for cross-cloud networking practice.
