Phase 1

Pull-Based GitOps

Constraint: The GCP VM (e2-micro) has only 1GB RAM, making standard CI/CD agents prone to Out-Of-Memory (OOM) lockups.

Setup: Written in native Bash, polling origin via systemd.timer to avoid agent execution footprints.

Phase 2

Push-Based IAP

Requirement: Instant event triggers while maintaining strict zero-ingress policies (all public inbound closed).

Setup: GitHub Actions establishing ephemeral SSH sessions tunneled exclusively through Google IAP's internal IP ranges.

Phase 3

Status Telemetry

Requirement: Real-time service metrics and system tracking without heavy monitoring agent resource overhead.

Setup: Nginx stub-status and a custom, lightweight Python micro-daemon running alongside Nginx via Docker Compose.

Key Engineering Decisions

Stealth Origin Architecture

The VM instance hosts no public IPs or port exposures. Egress is bridged via Cloudflare Tunnels and incoming management is secured behind Google Identity-Aware Proxy (IAP).

Runtime Privilege Separation

The web application container uses unprivileged execution contexts (UID 101), preventing local container escapes from gaining root authority on the Debian VM host.

Deterministic IaC Lock

All networking components, firewall policies, storage buckets, and instance templates are provisioned via state-locked Terraform scripts to assure instant disaster recovery.

Native Telemetry Gateway

Nginx's stub metrics are parsed directly by a daemon sidecar. This avoids installing bulky host-level logging scripts and keeps VM memory utilization minimal.

SRE Live Telemetry

Real-time health statistics read from the VM's kernel /proc filesystem via an isolated daemon sidecar.
