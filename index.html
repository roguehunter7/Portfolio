I specialize in architecting secure, automated infrastructure. This site serves as a live case study for a zero-ingress cloud environment, demonstrating the transition from initial resource constraints to an enterprise-grade CI/CD pipeline.

Phase 1: Bootstrapping

Native Resource Polling

Constraint: The GCP e2-micro instance is limited to 1GB of RAM. Standard CI/CD runners (like GitHub Actions Runners or Jenkins) posed a high risk of triggering Out-Of-Memory (OOM) events.

Architecture: A pull-based GitOps loop using systemd.timer and a native Bash script. The system polled the GitHub API every 2 minutes for SHA deltas, minimizing memory overhead.

Phase 2: Refactored

Push-Based IAP Tunneling

Requirement: Transition to an instant, push-based model while maintaining a zero-ingress security posture (no public open ports).

Architecture: Replaced polling with GitHub Actions. Utilized GCP Identity-Aware Proxy (IAP) to securely tunnel SSH deployments via Port 22 without exposing the port to the public internet.

Phase 4: Serverless

Cloud Run & WIF

Optimization: Managing a VM, Cloudflare tunnels, and OS-level systemd daemons added unnecessary operational overhead.

Architecture: Transitioned to Google Cloud Run (Serverless). Implemented Workload Identity Federation (WIF) for keyless GitHub Actions deployments via Artifact Registry.

System Architecture

Provisioned via Terraform using a GCS Remote Backend for state consistency across development environments.

The Serverless Transition (Phase 4)

Why we built the old architecture

Initially, the portfolio was hosted on a GCP e2-micro VM. Because of the strict 1GB RAM constraint, running standard CI/CD agents on the VM caused Out-Of-Memory (OOM) crashes. To solve this, we implemented a pull-based GitOps loop (Phase 1), evolved it into a push-based deployment using GCP Identity-Aware Proxy (IAP) tunneling to keep port 22 closed (Phase 2), and moved the Docker build process to GitHub Actions (Phase 3). We also ran a custom Python systemd daemon to track host-level CPU and RAM telemetry.

While this zero-ingress VM architecture was highly secure and an excellent exercise in Linux systems engineering, it carried significant operational overhead. We had to manually patch the OS, manage Cloudflare tunnels, and maintain custom deployment shell scripts and systemd services.

The Transition to Cloud Run

To achieve true "lazy" efficiency (the best code is the code never written), we nuked the VM entirely and migrated to a fully managed Serverless architecture.

  • Google Cloud Run: The Nginx container is now deployed to Cloud Run, which scales to zero when idle. No more OS patching, no more OOM errors, and no need to manage Cloudflare daemon tunnels.
  • Workload Identity Federation (WIF): We eliminated all long-lived service account keys and GitHub PATs. GitHub Actions now securely authenticates to GCP via short-lived OIDC tokens.
  • Artifact Registry & Terraform: Images are pushed to GCP Artifact Registry, and the entire Cloud Run service is declaratively provisioned via Terraform inside the GitHub Actions pipeline.

The Result: The legacy telemetry daemons and deployment scripts were deleted. We retained a purely stateless, highly scalable, and keyless infrastructure that requires zero maintenance. Deletion over addition.
